מדריך ה-Backend של ביס וסיר

המדריך מיועד למפתח Frontend (Angular / Nest בסיסי) שלומד FastAPI. כל הקטעים מבוססים על הקוד האמיתי ב-apps/recipe-service. שמות קבצים, פונקציות וקטעי קוד מופיעים באנגלית כמו שהם בקוד.

★ הליבה: 5 רעיונות

זו הקריאה של 15 דקות. שאר המדריך הוא חומר עזר: חוזרים אליו כשסטורי נוגע בנושא.

1. בקשה עוברת router → service → repository

ה-router מקבל בקשת HTTP ולא מחליט כלום. ה-service מכיל את ההחלטות (למשל "אין מתכון כזה, זו שגיאה"). ה-repository הוא היחיד ששואל את מסד הנתונים. זה כמו controller → service → data access ב-Nest. 

# apps/recipe-service/app/recipes/router.py
@router.get("/{recipe_id}", responses={404: {"model": ErrorResponse}})
def get_recipe(recipe_id: uuid.UUID, service: ServiceDep) -> RecipeRead:
    return service.get_recipe(recipe_id)

# apps/recipe-service/app/recipes/service.py
recipe = self._repository.get(recipe_id)
if recipe is None:
    raise AppError(404, ErrorCode.RECIPE_NOT_FOUND, "Recipe not found")

2. Depends הוא כמו inject()

פרמטר עם Depends אומר ל-FastAPI: "תכין את זה בשבילי ותעביר לפונקציה". כך ה-endpoint מקבל service מוכן, שמקבל repository, שמקבל Session של מסד הנתונים. אין new ידני, בדיוק כמו הזרקה ב-Angular. 

# apps/recipe-service/app/recipes/router.py
ServiceDep = Annotated[RecipeService, Depends(get_recipe_service)]

# apps/recipe-service/app/recipes/service.py
def get_recipe_service(
    session: Annotated[Session, Depends(get_session)],
    tags: Annotated[TagService, Depends(get_tag_service)],
) -> RecipeService:
    return RecipeService(RecipeRepository(session), tags)

3. מודלים של Pydantic הם DTOs

מחלקה ב-schemas.py מתארת את צורת ה-JSON שיוצא או נכנס. FastAPI מאמת לפיה את הקלט, ומסנן לפיה את הפלט: מה שלא מופיע בה לא נשלח ללקוח. זה כמו DTO עם class-validator ב-Nest, וגם כמו ה-interface שהיית כותב ב-TypeScript. 

# apps/recipe-service/app/recipes/schemas.py
class RecipeSummary(BaseModel):
    id: uuid.UUID
    title: str
    tags: list[TagRef]
    total_minutes: int | None
    photo: PhotoRead | None
    created_at: datetime

4. טבלאות SQLModel הן entities, ונפרדות מה-DTOs

מחלקה עם table=True ב-models.py היא טבלה במסד הנתונים, כמו entity ב-TypeORM. היא לא נשלחת ללקוח ישירות: ה-service ממיר אותה ל-DTO. כך שינוי בטבלה לא שובר את ה-API, ולהפך. 

# apps/recipe-service/app/recipes/models.py
class Recipe(SQLModel, table=True):
    __tablename__ = "recipe"

    id: uuid.UUID = Field(default_factory=uuid.uuid4, primary_key=True)
    title: str = Field(max_length=120)
    description: str | None = Field(default=None, sa_type=Text)
    base_servings: int
    created_by: uuid.UUID | None = None   # נשמר בטבלה, לא נחשף ב-RecipeRead

5. בדיקה קוראת ל-API כמו לקוח ובודקת את ה-JSON

בדיקה ב-pytest שולחת בקשת HTTP לאפליקציה (בלי לפתוח פורט) ובודקת את הסטטוס והגוף. כמו supertest ב-Nest. ה-client מגיע כפרמטר, ו-pytest מזריק אותו. 

# apps/recipe-service/tests/test_recipes_api.py
def test_unknown_recipe_is_404_with_a_code(client: TestClient) -> None:
    response = client.get(f"/api/recipes/{uuid.uuid4()}")
    assert response.status_code == 404
    assert response.json() == {"detail": "Recipe not found", "code": "recipe_not_found"}
הכי טוב ללמוד: להריץ את השרת ולשחק ב-/docs

1. התמונה הגדולה

איך בקשה מהדפדפן מגיעה למסד הנתונים.

  Browser (React SPA)
        │  GET /api/recipes/{id}
        ▼
  Vite dev server  (apps/web, port 4200)
        │  proxy: '/api/' → http://localhost:8000
        ▼
  uvicorn  (ASGI server, port 8000)
        │
        ▼
  FastAPI app  (app/main.py → `app`)
        │  matches the route, validates input, calls Depends(...)
        ▼
  router    (app/recipes/router.py)      ← מקבל את הבקשה ומחזיר תשובה
        │
        ▼
  service   (app/recipes/service.py)     ← כללי עסק
        │
        ▼
  repository (app/recipes/repository.py) ← שאילתות למסד
        │
        ▼
  SQLModel / SQLAlchemy session          ← ORM: מחלקות Python ↔ טבלאות
        │
        ▼
  SQLite file  apps/recipe-service/data/app.db
  • Browser – ה-SPA שלכם. הוא פשוט עושה fetch('/api/...').
  • Vite proxy – בפיתוח, Vite מעביר כל בקשה שמתחילה ב-/api/ לשרת ה-FastAPI בפורט 8000 (apps/web/vite.config.mts). כך הדפדפן רואה מקור (origin) אחד, והעוגייה של ההתחברות עובדת בלי CORS.
  • uvicorn – שרת ה-HTTP של Python. תפקידו דומה לשרת ה-HTTP של Node ש-Express רץ עליו: הוא מאזין לפורט ומעביר כל בקשה ל-FastAPI.
  • FastAPI app – האובייקט app ב-app/main.py. הוא מכיל את כל ה-routes ואת ה-error handlers.
  • router → service → repository – שלוש שכבות בכל מודול (AD-1). ה-router מדבר HTTP, ה-service מחליט, וה-repository שולף נתונים.
  • SQLite – קובץ אחד על הדיסק. אין שרת מסד נתונים נפרד.

2. מילון מהיר: Angular/Nest ↔ FastAPI

המושגים שאתם מכירים, ומה שמקביל להם בעולם Python.

בעולם שלכם (Angular / Nest) ב-FastAPI / Python הערות
Controller APIRouter (router.py) מגדיר @router.get(...) במקום @Get().
DI, inject(), קונסטרקטור Depends(...) פונקציה שמחזירה ערך, FastAPI מזריק אותה לפרמטר.
DTO עם class-validator, interface Pydantic BaseModel (schemas.py) ולידציה בזמן ריצה וגם טיפוסים. גם מייצר את ה-OpenAPI.
Entity של TypeORM SQLModel table=True (models.py) מחלקה שמייצגת טבלה.
Migrations של TypeORM Alembic (app/migrations/) קבצי גרסאות שמשנים את הסכמה בסדר קבוע.
onModuleInit / APP_INITIALIZER lifespan (app/main.py) קוד שרץ פעם אחת בעליית השרת, לפני הבקשה הראשונה, ופעם אחת בכיבוי.
ConfigModule / environment.ts pydantic-settings (app/core/config.py) קורא משתני סביבה ו-.env ומאמת אותם.
Jest + supertest pytest + TestClient בודק את האפליקציה בלי לפתוח פורט אמיתי.
npm uv מנהל חבילות ו-virtualenv (ב-Python אין node_modules).
package.json pyproject.toml שם, גרסה, תלויות וכלים.
package-lock.json uv.lock נעילת גרסאות מדויקת.
tsc --strict mypy (strict = true) בדיקת טיפוסים סטטית.
ESLint + Prettier ruff (lint + format) כלי אחד לשניהם.
Nx module boundaries (תגיות) import-linter (חוזים ב-pyproject.toml) אוכף מי מותר לייבא מה. שבירה = כשל ב-lint.
כלל אצבע: אם הכרתם Nest, החשיבה דומה. ההבדל המרכזי: ב-FastAPI הכול פונקציות, לא מחלקות עם דקורטורים בכל מקום.

3. בקשה אחת, צעד אחר צעד: GET /api/recipes/{id}

נלך על הבקשה הזו מההתחלה ועד התשובה, כולל מקרה ה-404. 

  Browser        Vite proxy     uvicorn/FastAPI      router          service           repository       SQLite
     │ 1. GET      │                  │                 │                │                  │              │
     │────────────▶│ 2. proxy         │                 │                │                  │              │
     │             │─────────────────▶│ 3. match route  │                │                  │              │
     │             │                  │ 4. validate id  │                │                  │              │
     │             │                  │ 5. Depends()    │                │                  │              │
     │             │                  │────────────────▶│ 6. get_recipe  │                  │              │
     │             │                  │                 │───────────────▶│ 7. get(id)       │              │
     │             │                  │                 │                │─────────────────▶│ 8. SELECT    │
     │             │                  │                 │                │◀─────────────────│◀─────────────│
     │             │                  │                 │                │ 9. not found? → AppError 404    │
     │             │                  │                 │                │ 10. tags query   │              │
     │             │                  │                 │◀───────────────│ 11. RecipeRead   │              │
     │             │                  │◀────────────────│ 12. JSON 200   │                  │              │
  1. הבקשה מגיעה ל-Vite. apps/web/vite.config.mts מכיל '/api/': 'http://localhost:8000', אז Vite מעביר את הבקשה לשרת הפייתון.
  2. uvicorn מעביר ל-FastAPI. app/main.py מרכיב את האפליקציה ב-create_app(), ומוסיף לכל router את הקידומת /api: 
    # apps/recipe-service/app/main.py
API_PREFIX = "/api"
...
api = APIRouter(prefix=API_PREFIX)
for router in ROUTERS:
    api.include_router(router)
app.include_router(api)
  3. FastAPI מתאים את ה-route. ב-app/recipes/router.py: 
    # apps/recipe-service/app/recipes/router.py
router = APIRouter(prefix="/recipes", tags=["recipes"])

@router.get("/{recipe_id}", responses={404: {"model": ErrorResponse}})
def get_recipe(recipe_id: uuid.UUID, service: ServiceDep) -> RecipeRead:
    return service.get_recipe(recipe_id)
    הנתיב המלא הוא /api/recipes/{recipe_id}. ה-responses= רק מתעד ב-OpenAPI שיכול להיות 404.
  4. ולידציה של הנתיב. recipe_id: uuid.UUID גורם ל-FastAPI לנסות להמיר את המחרוזת ל-UUID. מזהה לא תקין מחזיר 422 לפני שהקוד שלנו בכלל רץ (יש לזה בדיקה: test_malformed_id_is_a_422).
  5. הזרקת תלויות. ServiceDep הוא Annotated[RecipeService, Depends(get_recipe_service)]. FastAPI מריץ את get_recipe_service, שדורש get_session ו-get_tag_service. כברירת מחדל FastAPI מריץ כל תלות פעם אחת לכל בקשה ומשתף את התוצאה, כך ששני השירותים מקבלים את אותו Session: 
    # apps/recipe-service/app/recipes/service.py
def get_recipe_service(
    session: Annotated[Session, Depends(get_session)],
    tags: Annotated[TagService, Depends(get_tag_service)],
) -> RecipeService:
    return RecipeService(RecipeRepository(session), tags)
    get_session פותח Session חדש לבקשה וסוגר אותו אחרי שהתשובה נשלחה (ראו סעיף 7 על yield).
  6. ה-router קורא ל-service. הפונקציה get_recipe לא מכילה לוגיקה – היא רק מעבירה את הקריאה הלאה (AD-1: "routers contain no business logic").
  7. ה-service שואל את ה-repository. RecipeService.get_recipe קורא ל-self._repository.get(recipe_id). ה-repository בונה שאילתה עם selectinload כדי לטעון גם את המצרכים ואת השלבים בשתי שאילתות נוספות, אחת לכל קשר, ולא שאילתה לכל שורה (בלי N+1): 
    # apps/recipe-service/app/recipes/repository.py
statement = (
    select(Recipe)
    .where(Recipe.id == recipe_id)
    .options(
        selectinload(_attribute(Recipe.ingredients)),
        selectinload(_attribute(Recipe.steps)),
    )
)
return self._session.exec(statement).first()
  8. מקרה ה-404. אם recipe is None, השירות זורק AppError: 
    # apps/recipe-service/app/recipes/service.py
recipe = self._repository.get(recipe_id)
if recipe is None:
    raise AppError(404, ErrorCode.RECIPE_NOT_FOUND, "Recipe not found")
    הקוד מוגדר ב-app/core/errors.py כ-ErrorCode.RECIPE_NOT_FOUND = "recipe_not_found". מכאן ואילך הביצוע קופץ החוצה: הקוד שלמטה לא רץ.
  9. ה-handler הגלובלי ממיר לתשובה. register_error_handlers(app) רשם את _app_error_handler, שמחזיר JSON עם הסטטוס מהחריגה. הבדיקה מאשרת את הצורה המדויקת: 
    # apps/recipe-service/tests/test_recipes_api.py
assert response.status_code == 404
assert response.json() == {"detail": "Recipe not found", "code": "recipe_not_found"}
  10. המסלול המוצלח (הרשומה קיימת). השירות טוען את התגיות באמצעות TagService.get_tags([recipe.id]), שמריץ שאילתה אחת עם JOIN (ב-TagRepository.list_for_recipes) ומחזיר רשימת TagRef לכל מתכון, ממוינת לפי sort_order (מוצמדות קודם) ואז לפי שם.
  11. בניית ה-DTO. השירות ממיר כל מצרך ושלב לסכמה (_ingredient_read ו-StepRead) ומחזיר RecipeRead. זה לא אותו אובייקט שמופיע בטבלה (ראו סעיף 6).
  12. FastAPI מסריאליז. מכיוון שהפונקציה מוגדרת -> RecipeRead, FastAPI מכניס את התשובה לסכמה, ממיר Decimal למספר JSON, ומחזיר 200.
  13. סגירת ה-Session. אחרי שהתשובה נשלחה, ה-with Session(...) ב-get_session מסתיים וסוגר את החיבור.

5. מה קורה כשמריצים nx run recipe-service:serve

הפקודה מפעילה את ה-target serve מתוך project.json, וזה בעצם: 

# apps/recipe-service/project.json (serve)
"command": "uv run uvicorn app.main:app --reload --port 8000",
"cwd": "{projectRoot}"
  1. טעינת הקונפיגורציה. app/main.py מיובא, ובשורה app = create_app() בתחתית הקובץ נקרא get_settings(). זה קורא משתני סביבה ו-.env מתיקיית העבודה (env_file=".env"). אם JWT_SECRET חסר, או שיש COOKIE_SECURE=false בלי ENV=dev, התהליך נעצר עם הודעה ברורה (load_settings זורק SystemExit).
  2. בניית האפליקציה. create_app() יוצר FastAPI(...), רושם את ה-error handlers ומרכיב את כל ה-routers תחת /api.
  3. הרצת ה-lifespan. לפני שמקבלים בקשה ראשונה, uvicorn מפעיל את lifespan: 
    # apps/recipe-service/app/main.py
@asynccontextmanager
async def lifespan(_app: FastAPI) -> AsyncIterator[None]:
    data_dir = get_settings().data_dir
    run_migrations(data_dir)
    try:
        yield
    finally:
        get_engine(data_dir).dispose()
    הקוד שלפני yield רץ בעלייה, והקוד שב-finally רץ בכיבוי.
  4. יצירת ה-engine ו-pragmas. get_engine(data_dir) יוצר את התיקייה data/ אם היא חסרה, ובונה engine עבור sqlite:///.../app.db (הוא נקרא כבר מתוך run_migrations). על כל חיבור חדש נשלחות שתי פקודות: 
    # apps/recipe-service/app/core/db.py
cursor.execute("PRAGMA foreign_keys=ON")   # SQLite לא אוכף מפתחות זרים כברירת מחדל
cursor.execute("PRAGMA journal_mode=WAL")  # Write-Ahead Log: קורא וכותב לא חוסמים זה את זה
    בלי foreign_keys=ON, מחיקה בקסקדה לא הייתה עובדת. מצב ה-WAL נשמר בקובץ המסד עצמו, ולכן ליד app.db יופיעו גם app.db-wal ו-app.db-shm.
  5. מיגרציות. run_migrations מעביר את החיבור ל-Alembic ומריץ command.upgrade(config, "head"). app/migrations/env.py משתמש בחיבור הזה ומריץ את המיגרציות. בקובץ 0001 נוצרות הטבלאות ושמונת סוגי הארוחה שמוגדרים כברירת מחדל (עם UUID קבועים ושמות בעברית). שגיאה במיגרציה עוצרת את השרת.
  6. מוכן לשירות. uvicorn מתחיל להקשיב בפורט 8000. התיעוד זמין ב-http://localhost:8000/docs.
  7. כיבוי. ב-Ctrl+C, ה-finally קורא ל-dispose() על ה-engine, וסוגר את כל החיבורים.
--reload גורם לשרת להתחיל מחדש בכל שמירה של קובץ Python, בדומה ל-ng serve.

6. מודל הנתונים

הטבלאות, הקשרים, והסיבה שיש שני סוגי מחלקות.

  recipe  1 ────────< N  ingredient      (recipe_id → recipe.id, ON DELETE CASCADE)
    │     1 ────────< N  step            (recipe_id → recipe.id, ON DELETE CASCADE)
    │
    │     N ──< recipe_tag >── N   tag  (שני המפתחות זרים, CASCADE; PK מורכב)
    │
  tag:  id, name (≤40), pinned, sort_order
        UNIQUE (lower(name))   ← אותו שם לא יכול להופיע פעמיים (בלי הבדל אותיות)

טבלת recipe (עמודות מרכזיות)

עמודה טיפוס / הערה
id UUID, מפתח ראשי (AD-5)
title VARCHAR(120)
description, notes TEXT, אופציונלי. notes הוא שדה ההערות החופשיות של המתכון.
base_servings מספר מנות בסיס
prep_time_minutes, cook_time_minutes INTEGER, אופציונלי
source_url VARCHAR(2048), אופציונלי
created_by, updated_by UUID בלי מפתח זר עדיין (יתווסף בסטורי 2.1)
created_at, updated_at תאריכים תמיד ב-UTC (UtcDateTime)

טבלת ingredient

עמודה משמעות
recipe_id, position שייך למתכון, וסדר ההצגה
name, note שם המצרך וההערה שלו
amount, unit הכמות הנוכחית (NUMERIC(12,3)) והיחידה. NULL ב-amount = "לפי הטעם"
has_original, original_amount, original_unit הערך המקורי לפני העריכה הראשונה (FR-7). has_original מבדיל בין "במקור לפי הטעם" (שני השדות NULL) לבין "אין מקור בכלל"
source_amount, source_unit ערך אימפריאלי שמיבא המיר למטרי (FR-21). זה לא המקור של FR-7

טבלת step ו-recipe_tag

step: recipe_id, position, description (TEXT), ו-source_text – הטקסט לפני המרת טמפרטורה, כשהייתה המרה.

recipe_tag: רק שני מפתחות זרים, recipe_id ו-tag_id, שמרכיבים יחד את המפתח הראשי. הבעלות שלו היא של מודול tags (AD-25).

למה יש שני סוגי מחלקות?

טבלאות (SQLModel table=True) DTOs לקריאה (Pydantic, schemas.py)
מייצגות את מבנה ה-DB: עמודות, מפתחות, אינדקסים. מייצגות את מבנה ה-API: מה הלקוח רואה.
Recipe מכיל created_by ו-updated_by שלא חושפים. RecipeRead לא מכיל אותם.
התגיות של מתכון לא קיימות כעמודה; הן בטבלת tag ומקושרות דרך recipe_tag. tags היא רשימת TagRef מוכנה, שהשירות בונה.
amount ו-original_amount הם שני שדות נפרדים. IngredientRead מציג original כאובייקט אחד, ו-source רק כשיש ערך.
Decimal פנימי, מסד הנתונים מחזיק NUMERIC. בתשובה JSON מספר רגיל (Amount, AD-31).
photo לא קיים בטבלה של המתכון. photo כרגע None, עד סטורי 3.7.
הסיבה להפרדה: ה-API הוא חוזה יציב עם הלקוח (AD-3), ואילו הסכמה של מסד הנתונים משתנה לפי צורכי האחסון. כשמשנים עמודה, לא שוברים את ה-API. וכשמשנים את ה-API, לא נוגעים בטבלאות. כמו שב-Nest לא מחזירים את ה-Entity של TypeORM ישירות אלא DTO.

ב-app/recipes/models.py מופיע הקשר בין הטבלאות:

# apps/recipe-service/app/recipes/models.py
ingredients: list["Ingredient"] = Relationship(
    back_populates="recipe",
    sa_relationship_kwargs={
        "order_by": "Ingredient.position",
        "cascade": "all, delete-orphan",

7. תחביר Python שתפגשו

כל דבר עם מקבילה ב-TypeScript.

Type hints

# Python
def get(self, recipe_id: uuid.UUID) -> Recipe | None: ...
tags: list[TagRef]
// TypeScript
get(recipeId: string): Recipe | null
tags: TagRef[]

X | None = X | null. list[X] = X[]. ההבדל: ב-Python ה-type hints לא נבדקים בזמן ריצה. רק mypy בודק אותם, חוץ ממודלים של Pydantic ו-FastAPI שקוראים אותם וגם מאמתים לפיהם בזמן ריצה.

async def מול def

# app/recipes/router.py – endpoint רגיל
def list_recipes(service: ServiceDep) -> list[RecipeSummary]: ...

# app/main.py – lifespan הוא async
async def lifespan(_app: FastAPI) -> AsyncIterator[None]: ...

ה-endpoints של המתכונים הם def רגיל (סינכרוני). FastAPI מריץ פונקציה כזו ב-thread pool, ולכן גישה חוסמת ל-SQLite לא תוקעת את שאר הבקשות (ראו ההערה ב-app/core/db.py על check_same_thread). async def מקביל ל-async function ב-TS, אבל כאן הוא לא נחוץ. אפשר לערבב את שני הסגנונות באותה אפליקציה.

דקורטורים: @router.get

@router.get("/{recipe_id}", responses={404: {"model": ErrorResponse}})
def get_recipe(...): ...

דקורטור ב-Python הוא פונקציה שמקבלת פונקציה ומחזירה פונקציה. @router.get(...) דומה ל-@Get(':id') ב-Nest: הוא רושם את הפונקציה כ-route. ההבדל הוא שב-Python הדקורטור הוא קוד רגיל שרץ בזמן הייבוא, והפונקציה עצמה נשארת פונקציה רגילה שאפשר לקרוא לה.

with ו-yield (ב-dependencies)

# app/core/db.py
def get_session(...) -> Generator[Session]:
    with Session(get_engine(settings.data_dir)) as session:
        yield session

with דומה ל-try/finally שקורא ל-close() בסוף. yield בתוך dependency אומר: "מסור את הערך ל-endpoint, וכשהבקשה נגמרת חזור לכאן והמשך". הקוד שאחרי ה-yield (כאן: סגירת ה-Session ביציאה מה-with) רץ אחרי שה-endpoint סיים והתשובה נשלחה, גם אם נזרקה חריגה.

Annotated

ServiceDep = Annotated[RecipeService, Depends(get_recipe_service)]
def list_recipes(service: ServiceDep) -> ...

דומה להזרקה דרך הקונסטרקטור ב-Nest: constructor(private service: RecipeService). Annotated מצמיד לטיפוס מטא-דאטה, כאן ההוראה "הזרק את התוצאה של get_recipe_service". ההגדרה ServiceDep נכתבת פעם אחת, ואז משתמשים בה כמו בטיפוס רגיל בכל endpoint.

הטיפוס X | None כפרמטר

description: str | None = Field(default=None, sa_type=Text)

שדה אופציונלי עם ברירת מחדל None, שקול ל-description?: string | null.

f-strings

f"sqlite:///{data_dir / DB_FILENAME}"
f"Route {route.path} has no tag; every router needs tags"

שקול ל-template literal: `sqlite:///${dataDir}`. אפשר גם להוסיף עיצוב אחרי נקודתיים, למשל {price:.2f}.

Comprehensions

# list comprehension
[_ingredient_read(item) for item in recipe.ingredients]
# dict comprehension
{recipe_id: [] for recipe_id in recipe_ids}

// TypeScript
recipe.ingredients.map((item) => ingredientRead(item));
Object.fromEntries(recipeIds.map((id) => [id, []]));

שימו לב: prep or 0 ב-total_minutes דומה ל-prep || 0 ב-JS ולא ל-??. הוא מחליף ב-0 כל ערך "ריק" (None, 0, מחרוזת ריקה), ולא רק None. כאן זה לא משנה, כי 0 מוחלף ב-0.

פונקציות נוספות ששווה להכיר

  • self ב-method הוא this, אבל מועבר במפורש. __init__ הוא הקונסטרקטור.
  • _name (קו תחתון) הוא "פרטי" בהסכמה בלבד, כמו private ב-TS, אבל לא נאכף.
  • True/False/None = true/false/null.
  • class X(StrEnum) הוא enum של מחרוזות (Unit.KG == "kg").
  • lambda x: ... = arrow function קצרה.

10. מילון מונחים

מונח הסבר קצר
ASGI ממשק סטנדרטי בין שרת (כמו uvicorn) לאפליקציה (כמו FastAPI), כך שאפשר להחליף כל צד. דומה לחוזה (req, res) שבין שרת ה-HTTP של Node לבין Express.
uvicorn השרת שמאזין לפורט ומריץ את אפליקציית ה-ASGI.
Pydantic ספריית ולידציה וטיפוסים. מגדירה את הסכמות של הבקשות והתשובות.
pydantic-settings קורא משתני סביבה ו-.env לתוך מחלקת Settings מאומתת.
SQLAlchemy ה-ORM של Python: ממפה מחלקות לטבלאות, ומנהל את ה-engine והחיבורים למסד הנתונים.
SQLModel שכבה מעל SQLAlchemy ו-Pydantic, שמאפשרת להגדיר מחלקה אחת שהיא גם טבלה וגם סכמה של Pydantic. בפרויקט הזה בוחרים להפריד: טבלאות ב-models.py ו-DTOs ב-schemas.py.
Session יחידת עבודה מול ה-DB. נפתחת לכל בקשה ונסגרת בסוף.
Alembic כלי מיגרציות ל-SQLAlchemy. כל שינוי סכמה הוא קובץ עם upgrade().
Migration (מיגרציה) קובץ גרסה שמשנה את הסכמה. רץ פעם אחת, ונרשם בטבלת alembic_version.
Dependency (Depends) פונקציה שמזריקה ערך לפרמטר של endpoint. אפשר לשרשר.
Lifespan הקשר async שרץ בעלייה ובכיבוי של האפליקציה.
Router (APIRouter) קבוצת endpoints עם קידומת ו-tags, מקביל ל-Controller.
Aggregate (AD-4) המתכון כיחידה אחת: המצרכים והשלבים שייכים אליו ונשמרים יחד.
WAL Write-Ahead Log: מצב של SQLite שבו קריאות ממשיכות גם בזמן כתיבה.
Pragma הגדרה ספציפית ל-SQLite, כמו foreign_keys=ON.
import-linter כלי שאוכף כללי תלות בין מודולים, כמו תגיות Nx.
AD-xx החלטת ארכיטקטורה מתוך ה-ARCHITECTURE-SPINE (_bmad-output/planning-artifacts/architecture/).
DTO אובייקט העברה. במקרה שלנו: מחלקה ב-schemas.py לקלט או לפלט של ה-API.
