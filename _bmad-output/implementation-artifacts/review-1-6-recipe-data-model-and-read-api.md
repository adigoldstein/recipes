# Review: Story 1.6 Recipe data model and read API

Status: ready for Adi's review. Nothing is committed or pushed.

Spec: `_bmad-output/implementation-artifacts/spec-1-6-recipe-data-model-and-read-api.md`

## Rework 2026-10-27: plain tags, no meal types (Adi)

Meal types are gone and everything is plain tags. Story 1.6 is committed locally (`4bea088`, not pushed), so the first migration was changed in place, not a new one.

- `tag(id, name, pinned, sort_order)`. The `group` column and `TagGroup` are gone. `pinned` tags are the quick-filter chips in the library (Story 1.9). Unique index is now `uq_tag_lower_name` on `lower(name)`.
- A recipe has 0..n tags, and none is required. The "exactly one meal type" rule and the 500 for a missing meal type are removed.
- The migration seeds 13 pinned tags in this order, `sort_order` 0 to 12: בוקר, בראנץ', צהריים, ערב, נשנוש, עיקרית, תוספת, מנה ראשונה/סלט, מרק, מאפה, קינוח, משקה, רוטב/ממרח. Seven of them keep the old fixed UUIDs, six are new. "אחר" is gone.
- `RecipeSummary` and `RecipeRead` return `tags: list[TagRef]`, ordered by `sort_order` (NULLs last) then name, in one query. `meal_type` is gone from both. `TagAssignment` is gone; `TagService.get_assignments` became `get_tags`, returning `dict[recipe_id, list[TagRef]]`.
- Docs follow: PRD (FR-1, 3, 12, 22 to 24, F10), `epics.md` (1.6, 1.9, 3.1 to 3.3, 4.1, 4.2, 5.2), spine (AD-7, AD-24, AD-25 and the filter rules), memlogs, UI component inventory, UX documents, sprint-status story keys, epic-1 context and the spec.
- Epic 4 (Story 4.1) now covers a tag editor that can add, rename, delete (removes the tag from its recipes, with a confirm that shows the usage count) and pin or unpin tags. Story 1.9 owns the pinned chip row (multi-select, AND), Story 4.2 the "עוד תגיות" all-tags sheet.

## Decisions applied (Adi, "All a")

1. `ingredient.has_original` (BOOLEAN, default false) separates "originally to taste" (`original` = `{amount: null, unit: null}`) from "no original" (`original` = null).
2. Class-based `RecipeRepository`, `RecipeService`, `TagRepository`, `TagService`, wired by `Depends` providers (`get_recipe_service`, `get_tag_service`).
3. `tags.service` returns `TagRef` lists (`get_tags`). `tags.schemas` and `photos.schemas` are public: their import-linter contracts now protect only router, repository and models.
4. Migrations in `app/migrations/`, `alembic.ini` at the project root, `app/core/migrate.py` called from the FastAPI lifespan.
5. `tag.sort_order` (nullable) set 0 to 12 for the 13 default pinned tags. No `GET /api/tags` (Story 1.9).
6. No photo columns. `photo` is `PhotoRead | null` in `RecipeSummary` and `RecipeRead` and is always null until Story 3.7.

## Notes and open points (not blocking)

- **`Unit` / `SourceUnit` live in `app/recipes/units.py`.** import-linter forbids `imports` from depending on `recipes`, but `DraftRecipe` (Epic 5) needs `Unit`. That story will have to move the enums (for example to `app/core`) or relax the contract. Flagging it now rather than deciding it here.
- **A recipe may have no tags.** `tags` is an empty list, not an error. Nothing requires a tag on write (Story 3.1).
- **SQLite DDL is not transactional through pysqlite**, so a migration that fails halfway can leave some tables behind. Fine for this one-file schema; worth revisiting if migrations grow.
- The `ErrorResponse` for framework 404/405 (deferred since Story 1.1) is still open. Only `recipe_not_found` has the `{detail, code}` shape.
- Amount serialization: `Decimal` is exact inside, `float` on the wire (`0.333`, `1.5`). Three decimals always round-trip.

+## Decisions (Adi, 2026-10-27: "All a")

+def add_tag(session: Session, name: str, *, pinned: bool = False) -> Tag:
+    tag = Tag(name=name, pinned=pinned)
+    session.add(tag)
+    session.commit()
+    return tag
+

+def add_recipe(
+    session: Session,
+    *,
+    title: str = "שקשוקה",
+    tags: Sequence[Tag] = (),
+    ingredients: Sequence[Ingredient] = (),
+    steps: Sequence[Step] = (),
+    created_at: datetime | None = None,
+    **fields: Any,
+) -> Recipe:
+    values: dict[str, Any] = {"title": title, "base_servings": 4, **fields}
+    if created_at is not None:
+        values["created_at"] = created_at
+    recipe = Recipe(**values)
+    recipe.ingredients = list(ingredients)
+    recipe.steps = list(steps)
+    session.add(recipe)
+    session.flush()
+    for tag in tags:
+        session.add(RecipeTag(recipe_id=recipe.id, tag_id=tag.id))
+    session.commit()
+    session.refresh(recipe)
+    return recipe
+

+

+    return Ingredient(recipe_id=_UNSET, position=position, name=name, **fields)

+
+def step(position: int, description: str, **fields: Any) -> Step:
+    return Step(recipe_id=_UNSET, position=position, description=description, **fields)
